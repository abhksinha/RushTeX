# SUPER IMPORTANT: Guarded Direct Lowering (GDL), how every native feature is built from now on (living guideline)
Author: abhi+claude | Date: 2026-10-24 (living guideline: update in place, record each change in a dated note)

## Context
`native-architecture.md` already says native code "builds node lists directly into the exact typesetting core" and front ends produce "a command stream of IDs, never strings". The native job did not do that yet. It runs the document's text through TeX's token machine (lex, intern, expand, main loop), and 13 native commands (`vspace`, `table_of_contents`, `normal_cr`, `cite`, `begin_env`, `wide_accent`, `text_accent`, `set_length`, `math_alphabet`, `install`, `end_env`, `bib_open`, `wide_accent_end`; 44 calls of `tex()`) write TeX source text that is lexed and expanded again.

On the 29-page benchmark (2026-10-24, `scripts/stage_profile.py`) that token machine is about 35% of the job: TeX main loop 9.6%, expansion and input 8.0%, native commands 11.6%, characters 5.7%. Start-up rebuilds a fixed state on every process: 43% of a one-line document.

The user decided on 2026-10-24:
- the old style is not followed again;
- the speed floor is **40–50× fewer CPU instructions than one pdflatex run**, long documents included.

**Name (user, 2026-10-24): Guarded Direct Lowering, GDL.** *Guarded*: the pre-scan proof, with the engine as fallback when it fails. *Direct*: no interpreter in between. *Lowering*: source to typed operations to nodes and PDF. "The GDL path", "a GDL builder", "a GDL guard condition".

This guideline is how all work is done from now on: kernel, packages, the user's own language. It refines `native-architecture.md`, which stays binding. Where they differ, this is the newer word on *how* to build.

## Decision

### 1. The pipeline of a native document (the GDL path)
1. **Pre-scan proof.** One pass over the source (`scan_with`, `predict`) proves the document uses only what the native path implements, unchanged. It decides native or engine for the whole document (§2a of `native-architecture.md`).
2. **Direct compiler.** Source bytes become typed operations: text runs, command IDs with parsed arguments, and math atoms. No tokens, no interning of known names, no expansion.
3. **Node builders.** Each operation calls a typed builder: a character run, glue, a kern, a penalty, a box, paragraph start and end, a math list, a mark, an insertion.
4. **Exact core.** Line breaking, hyphenation, packing, Appendix G, page building and alignment, as tex.web computes them.
5. **PDF.** Glyphs and rules straight to the content stream; fonts from carried programs.

TeX's token machine runs only for what a document defines itself (`\newcommand`, `\def`): their expansion feeds the same builders. For everything else the document falls back to the engine. A native document never pays for interpretation of LaTeX.

### 2. Rules for native code (the new style)
- **R1: no TeX text.** A native command never produces TeX source, a token list it built from a string, or a `format!` of TeX. It calls builders and sets state through typed APIs (`eqtb` by register ID, fonts by ID). Writing `tex("...")` in new code is a defect. **The user's own tokens are the one exception, and they stay tokens:** an argument the document wrote (a `\cite` note, a `\mathbf` argument) goes back to the token machine unchanged, followed only by *typed* closers (`Token::char(Cat::EndGroup, '}')`, `Token::cs(id)`), never lexed text. A closing character that would form a word with the document's next character (`\cite`'s final `]`) also stays a token, so its ligatures and kerns are TeX's (§1038).
- **R2: IDs, not names.** Every name the native path knows is a generated constant or a perfect-hash ID (`names.rtdb`). Nothing is interned or string-compared at run time on the hot path.
- **R3: build time over run time.** State that is the same for every document is generated by `rushtex-gen` and loaded in place. That covers the start state after class load, symbol records, class values, font records and glyph names. Each table:
  - is binary records, never text lines parsed at use;
  - has a self-check in its generator;
  - has a stale-table unit test;
  - is checked by CI `cmp` against a regeneration.
- **R4: one guard.** Every assumption the direct path makes (catcodes, an unredefined command, an untouched internal, a known package option) is a condition in the pre-scan. Each condition has a probe that violates it and must fall back. No assumption lives anywhere else.
- **R5: the core's meaning is fixed.** Changes to `engine_linebreak`, `engine_hyph`, `engine_pack`, `engine_mlist` and `engine_page` may change data layout and add memos, never results. Cite the § (`// §863`).
- **R6: general TeX rules, no shortcuts.** Builders implement TeX's rules for every input: modes, groups, space factor, ligatures and kerns (§1034–§1040), Appendix G. Nothing is special-cased for a document, a formula or a symbol.
- **R7: data plus mechanisms.** A package splits into two parts:
  - **data:** symbols, parameters, option tables, harvested from the package by LaTeX at generation time;
  - **mechanisms:** what it does, written as Rust over the builders.

  Its macros are never run, and never hand-copied.
- **R9: drop only what nothing can observe.** A side effect of a LaTeX macro may be left out exactly when the pre-scan rejects every way a document could read it. `\sp@ce@skip` has an `@` name no native document may use, so not setting it is correct; `\dimen@` is `\dimen0`, which a document can read, so it is set. Identical observable output, not identical workflow.
- **R8: least data movement.** Hot data is flat arrays, IDs and ranges (§5–§7 of `native-architecture.md`), with SoA where loops read one field. No per-item allocation, no `HashMap` for static data, no copying of node lists or strings where an ID or range will do.

### 2a. The base every command is built on (2026-10-24)
Translation is cheap when three things hold. They are built once, not per command:
1. **The builder base is TeX's own `main_control` table (§1045).** Every macro bottoms out in about 30 appending cases: character run, space, glue, kern, penalty, rule, box begin/end, insert/adjust, mark, math shift, math character, accent, discretionary, leaders, unbox, par, indent, italic correction, alignment. Each `Prim::X` arm becomes "scan operands; `build_x(...)`", and natives call the same `build_x`. A native then cannot diverge from the engine's behaviour, by construction. Done so far in `engine_build.rs`: `build_glue`, `build_penalty`, `build_rule`, `build_adjust`, `build_hbox`, `build_control_space`, and `build_text` on the byte-run character source (`Machine::text_run`, read by `main_loop`'s lookahead).
2. **One registration row per command.** Name, argument signature (xparse-style `s o m`), native function, mode mask, package. The pre-scan, `predict`, `names.rtdb` and argument reading are all derived from it, so a new command needs no guard code of its own.
3. **The oracle checks state and nodes, not only pixels.** A probe runs on the engine and natively, and the node list of each page and the integer, dimension and glue registers at `\end{document}` are compared. A wrong penalty or a missed register shows in one run.

Not built: a macro-to-Op lowerer (no measured need), and environment bodies as TeX strings (they become begin/end natives over a typed frame, as `Doc::lists` is).

### 3. Recipe for porting a feature or package
1. Pick it from measured blockers (`TOP=N scripts/native_gaps_census.sh arxiv-corpus`, `parity-testing gaps`).
2. Read its definition (`scripts/refindex.py`, the `.dtx`, tex.web §). Search memcastle before designing.
3. Split it into data (generated) and mechanisms (builders, R7). Add its guard conditions and their fallback probes (R4).
4. Add a probe document in `scripts/native_probes/`. It must be identical to pdflatex: zero shift, and pixels at 300 and 600 dpi.
5. Measure the instruction delta on the benchmark documents (§5).
6. Run the gates (§4), write a journal note, `memcastle save`, and commit.

### 4. Gates (every change)
- `scripts/native_probes.sh` (all probes plus `scripts/bench/native-29p.tex`) identical.
- `parity-testing zero --engine --pixels --all` 85/85, also with `RT_EMBED_FIRST=1`.
- `cargo test --release`, and clippy in all three configurations.
- `scripts/engine_suites.py` and `scripts/leak_audit.py`.
- Instruction counts: no benchmark document gets worse.

### 5. Speed budget
- **Floor:** 40–50× fewer instructions retired than one pdflatex run (`/usr/bin/time -l`, median of at least 5), on every native document.
- **Benchmark documents: 10 pages or more only (user, 2026-10-24).** Short files hide per-page cost behind start-up and are not used for speed claims. `scripts/bench/gen_bench.py` writes the generated ones.

  | Document | Pages | Limit at 40× | pdflatex, one run | rushtex (2026-10-24) |
  |---|---|---|---|---|
  | `native-math-20p` | 20 | 95M | 3,820M | 155M (25×) |
  | `native-29p` | 29 | 110M | 4,389M | 231M (19×) |
  | `native-text-61p` (real prose of six LaTeX guides) | 61 | 88M | 3,515M | 362M (10×) |

- A commit that raises any document's count needs its reason in its note.
- **Wall clock and cycles** are reported beside instructions. A cycle ratio far below the instruction ratio means cache misses or page-ins, and is work for R3 and R8.

### 6. Migration order (the old style leaves)
1. The 13 TeX-text natives move to builders (R1); `tex()` is deleted.
2. The direct compiler for text runs and known commands, behind the pre-scan proof.
3. The generated start state (R3), so a one-line document loads, not builds.
4. The core's layout: a hyphenation memo, and line breaking with an index-linked active list and SoA widths.
5. PDF: a direct glyph path for fonts without a VF, and a cheaper deflate setting (pages and glyphs unchanged).

### 7. What is ported, and what stays (folded from `native-port-plan.md`, 2026-10-24)
- **Leaves the product:** interpretation of `latex.ltx`, expl3 and the `.sty`/`.cls` macro code, TeX Live files, the format build, `kpsewhich`, `.aux` files.
- **Stays:** the exact core, and TeX's full macro language for the document's own code (`\def` with delimited parameters, `\expandafter`, `\csname`, catcode changes, `\newcommand`; tex.web §366–§401, §487–§510). It expands only the document's own macros; every LaTeX command it reaches is native.
- **Packages fall in five classes:** (a) macro-programming libraries (etoolbox internals, keyval, kvoptions, the `if*` packages, expl3 internals): subsumed, zero port; (b) programming commands documents call (`\ifthenelse`, calc in `\setlength`, `\newtoggle`, `\NewDocumentCommand`): native builders; (c) feature packages (hyperref, graphicx, amsmath, xcolor, booktabs, geometry, …): ported in census order; (d) classes (article, report, book, amsart, IEEEtran, revtex): data tables plus behaviour; (e) font packages (lmodern, mathptmx, helvet, …): data only, NFSS tables and metrics from `rushtex-gen`.
- **Order comes from real papers** (`scripts/native_gaps_census.sh` over the arXiv sample), not from the CTAN corpus, whose `.dtx` manuals overweight doc/ltxdoc and hyperref. The 85 corpus documents stay the acceptance gate.

### 8. Overridable internals (folded from `native-port-plan.md`)
Documents redefine kernel internals (`\@makecaption`, `\@seccntformat`, `\thesection`, `\labelenumi`, `\arraystretch`, `\figurename`, …). Every internal a native command uses keeps its control-sequence name; the native reads the name's current meaning (one comparison of the meaning word): still native, a direct call; redefined, the document's macro runs, or the pre-scan sends the document to the engine when the native cannot honour it. Example: `\rmdefault` and kin are read from the preamble (`2026-10-24-native-font-families.md`); the font defaults the native job does not read are compared with the class's and fall back when changed.

## Rejected
- **Natives that emit TeX text** for the token machine. They pay for lexing, interning and expansion twice, and give two styles to debug.
- **The token machine for native documents.** Once the pre-scan has proved the document, interpretation decides nothing.
- **Per-document or per-formula shortcuts.** They break the generalization to full TeX and turn every new package into patches.
- **Parsing table text at run time, runtime `HashMap`s for fixed data, and rebuilding fixed state per process** (R2, R3).
- **Measuring against pdflatex's two or three runs as the floor.** The user's floor is one run.
