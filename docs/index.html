The same PDF as pdfLaTeX. A fraction of the work.

RushTeX is a LaTeX compiler written from scratch in Rust, with no runtime dependencies and no unsafe code. Its output is checked against pdfLaTeX glyph for glyph and pixel for pixel. On the 12-page project description it takes 32.9× fewer CPU instructions than one pdfLaTeX run, and 103.9× fewer than the three runs pdfLaTeX needs to finish that document.

Why RushTeX exists

LaTeX's output is the standard of scientific publishing. Its way of producing that output dates from machines with a few hundred kilobytes of memory.

The problem

pdfLaTeX interprets LaTeX's macros one token at a time, touches every character about sixteen times on the way to the PDF, and writes an auxiliary file so that a second and third run can fill in references and the table of contents. A full TeX Live installation is several gigabytes. Each compile repeats all of this for the whole document, even after a one-letter edit.

Online editors

Collaborative editors such as Overleaf compile every user's document on their own servers, again on each save, for millions of users. The cost of a compile is paid in server CPU, in queueing when load peaks, and in the seconds a writer waits to see the page. A compiler that does a thirtieth of the work for the same PDF cuts that cost directly, and one that runs in the browser removes it from the server altogether.

The approach

Keep everything that decides where ink goes on the page: TeX's line breaking, hyphenation, page building and mathematics, integer for integer. Remove or move to build time everything else: macro expansion for known commands, the format file, the auxiliary-file round trip, per-character work for repeated words. The result must be the identical PDF; the workflow does not have to be.

What it is not

Not a new markup language and not an approximation of LaTeX. A document that compiles with pdfLaTeX should compile with RushTeX and give the same pages. Features beyond LaTeX are allowed only as opt-in additions that never change a standard document's output.

How it works

Two paths share one exact typesetting core. A document takes the native path when a pre-scan proves that every command in it is supported; otherwise it runs whole on the engine.

Native path: Guarded Direct Lowering

LaTeX's kernel and packages rewritten in Rust. No format file, no TeX files read, no .aux, one pass. Class parameters, font metrics, font definitions and hyphenation patterns are generated into tables at build time and carried in the program.

Engine path: TeX, reimplemented

TeX and pdfTeX from tex.web, written again in Rust: tokenizer, expansion, conditionals, boxes, line breaking, alignments, page builder, math lists, fonts, virtual fonts, PDF output. It runs the real LaTeX format on an installed TeX Live and gives pdfLaTeX's exact output. It is the fallback and the reference the native path is checked against.

1Pre-scan proofReads the source once. Accepts or refuses the whole document before anything runs.
2Direct compilerEach command becomes calls of typed node builders. Known names are numbers.
3Node buildersAppend boxes, glue, kerns and penalties. A word is one node with its summed width.
4Exact coreLine breaking, pages and math with TeX's own arithmetic. Never adjusted afterwards.
5PDFEach finished page becomes PDF operators, as pdfTeX writes them.

The rules every native feature follows

  • No TeX textA native command builds nodes, never strings of primitives to be read back.
  • Numbers, not namesA name known in advance is a number at run time.
  • Build time firstWhatever depends only on fixed data is computed when the program is built.
  • One guardA document is accepted or refused once, before it runs.
  • Fixed resultsThe core's results are final; nothing corrects them later.
  • General rulesA behaviour comes from the rule that defines it, never a per-case tweak.
  • Data and mechanismsTables hold the data; code holds the mechanisms.
  • Least movementData moves as little as possible; structures follow their access pattern.
  • Only the unobservableA step is dropped only if nothing on the page can observe it.

Exactness

“Zero shift” means the RushTeX PDF and the pdfLaTeX PDF agree on everything a reader or a program can observe.

What is compared

Every glyph and its position in scaled points, every rule and path, every colour, link, destination and outline entry, and every pixel of the pages rendered at 300 dpi. New native features are also checked at 600 dpi and node by node against the engine's page boxes.

Against what

A pinned TeX Live 2026 snapshot with a checksummed file list, so references, generated tables and CI all come from the same sources. 85 CTAN documents, 2,137 pages, compile at zero shift on the engine path.

How

parity-testing, an independent checker in Rust with its own PDF reader, inflate and renderer comparison. Exactness is derived from tex.web and latex.ltx, never tuned per document; code cites the section it implements.

What works today

The engine path compiles what pdfLaTeX compiles, given a TeX Live installation. The native path is younger and growing in the order of the papers each feature unblocks.

Native: document
article class with its size, paper, draft, twoside and landscape options; \maketitle, abstract; sections to subsubsection, run-in headings; \tableofcontents, forward \ref and \pageref in one pass; footnotes; page styles.
Native: text
Paragraphs with TeX's line breaking and hyphenation; ligatures and kerns; font families, series, shapes and sizes from the NFSS tables, including \rmdefault and Times; accents; itemize, enumerate, description; center, flush environments, verbatim; \\, \vspace, \hspace, \newpage.
Native: floats and tables
figure and table with \caption and the float queue; tabular with rules, \multicolumn and \cline.
Native: mathematics
Inline and display math, equation, TeX's Appendix G layout; amssymb and amsfonts with their alphabets.
Native: references
\cite with thebibliography; \label/\ref resolved in memory.
Not native yet
graphicx, amsmath environments (align, \text, equation*), package options, UTF-8 input, hyperref, BibTeX .bbl, amsthm, natbib, booktabs, geometry, xcolor, two columns, other classes. Documents that use them run on the engine path. Of a sample of 169 arXiv papers, 1 runs natively today; the list above is ordered to raise that number fastest.
Your own .sty and .cls
A document with its own style files always runs whole on the engine, with the exact output, rather than being ported.
Implementation
About 143,000 lines of Rust, standard library only, #![forbid(unsafe_code)]. Builds as a command, a Rust library and a C-compatible dynamic library. 366 unit tests; Clippy with warnings as errors.

Where it can go: WebAssembly and the client side

Because RushTeX uses only Rust's standard library and carries its fonts and tables inside the program, the same code that runs on a server can run in a browser. Each item says what exists today and what is planned.

WebAssembly build Today
The library compiles for wasm32-unknown-unknown: 27 MB with the fonts, metrics, class tables and hyphenation patterns included. A browser API and a font subset for the web are not yet published.
Client-side compile for online editors Planned
An editor like Overleaf could compile in the writer's browser instead of on its servers. Server CPU per compile drops to zero, compiles no longer queue at peak hours, and the writer sees the page without a network round trip. The server can keep the engine path for documents the native path does not yet cover.
Incremental compile Planned
The state is designed to be checkpointed per block: after an edit, only the changed paragraphs are set again, page breaking runs until it matches the previous layout, and only the changed pages are written. The target is under 16 ms per typical edit, one display frame, so the PDF updates as you type.
Tablets and phones Planned
With no TeX installation and about 10–18 MB of memory per document today, a full LaTeX compile fits on an iPad or a phone, offline, with the same PDF a journal would produce.
Privacy Planned
A manuscript compiled on the device never has to leave it: useful for unpublished results, peer review and confidential reports.
Servers and CI Today
One static program with no TeX Live for native documents: small containers, fast cold starts, one pass instead of three for documents with references.

Contribute

RushTeX is an attempt to give the world's scientific typesetting system a modern, exact and efficient implementation. It is larger than one person. Contributions of every size are welcome: a package ported natively, a gap found, a benchmark on your machine, a document that should work and doesn't.
