\section{Introduction and Architecture Overview}
The \textbf{rushtex} engine is a LaTeX-to-PDF compiler written entirely from scratch in pure safe Rust whose output is identical to pdfLaTeX's. It compiles a document on one of two paths: the native job, which typesets every construct as ported Rust in one pass when its pre-scan accepts the whole document, and the TeX engine (\texttt{tex.web} and pdfTeX ported to Rust), run on the LaTeX format as \texttt{pdflatex} runs it, for every document the native job declines.

\subsection{Core Design Principles}
\begin{itemize}
\item \textbf{100\% Pure Safe Rust}: Enforced at crate root via \texttt{\#![forbid(unsafe\_code)]}. Zero raw pointer dereferences, zero FFI, zero undefined behavior.
\item \textbf{Zero Dependencies}: Compiles using exclusively the Rust standard library. No third-party crates, no \texttt{libc}, and no external compression libraries.
\item \textbf{Hardware-Constrained Efficiency}: Strict cache-conscious data structures engineered to maximize L1, L2, and L3 CPU cache locality.
\item \textbf{One Pass for Native Documents}: The native job reads the source once and needs no format, no TeX files and no auxiliary-file reruns; cross-references are resolved in memory.
\item \textbf{Exact Fallback}: A document that uses any command the native job has not ported runs whole on the TeX engine, so no document is typeset approximately.
\item \textbf{Builds Without the Engine}: Without the default \texttt{oracle} feature the crate builds the native job alone; a document it declines is then reported as needing TeX Live.
\end{itemize}

\subsection{L1 Cache-Line Alignment (12-Byte Nodes)}
Modern CPU cores spend significant time waiting on DRAM latency. To maintain maximum memory throughput, \texttt{rushtex} optimizes data representation around the 64-byte L1 data cache line. A node of a box's list (\texttt{tex.web} \S133--\S161) is 12 bytes, and the meaning of a control sequence is at most 16 bytes:

\begin{lstlisting}[language=Rust, numbers=left]
// A node: a kind, a subtype, a font and two words (12 bytes)
// A control sequence's meaning: at most 16 bytes
// Four meanings fit per 64-byte L1 cache line
assert!(std::mem::size_of::<Meaning>() <= 16);
\end{lstlisting}

What does not fit in a node (a box's dimensions and glue setting, a glue specification, a rule's three dimensions) lives in a side table the node indexes. A finished list is a span of the node arena and never changes, so \verb|\copy| shares a box instead of copying its list.

\subsection{Direct Lowering Without Tokens}
The native job's direct compiler turns source bytes into typed operations (text runs, command identifiers with parsed arguments, and math atoms) without building tokens, interning known names or expanding macros. Only what a document defines itself (\verb|\newcommand|, \verb|\def|) runs on TeX's token machine, feeding the same node builders.

\subsection{The Pre-Scan: Choosing the Path}
Before typesetting, \texttt{rushtex} reads the source once to decide which of its two paths compiles the document:
\begin{itemize}
\item \textbf{Whole-Document Proof}: The pre-scan proves that the document uses only the commands, environments, packages and options the native job implements exactly. One unported construct sends the whole document to the TeX engine.
\item \textbf{Reported Reason}: With \texttt{RT\_NATIVE\_WHY=1} the compiler prints why the native job declined; for this manual it is the \texttt{listings} package.
\item \textbf{Blocker List}: \texttt{rushtex document.tex --native-gaps} lists everything in a document the native job does not take yet.
\item \textbf{No Mixed Pages}: The decision covers the whole document, so no page is part native and part engine.
\end{itemize}

\subsection{Paragraphs: \texttt{tex.web}'s Line Breaking}
Paragraphs are broken and hyphenated on both paths exactly as \texttt{tex.web} computes them:
\begin{itemize}
\item \textbf{Knuth--Plass Line Breaking}: Paragraphs are broken by the algorithm of \texttt{tex.web} \S813--\S890, with the same badness, demerits and passes, so every line ends where pdfLaTeX ends it.
\item \textbf{Liang Hyphenation}: Hyphenation uses the LaTeX format's English patterns, carried as a generated table (\texttt{assets/tables/hyph-en.rtdb}).
\item \textbf{Exact Arithmetic}: Widths, glue and penalties are scaled integers (1/65536 pt), as in TeX, never floating point.
\end{itemize}

\subsection{Mathematical Typesetting: TeX Appendix G}
Formulas are converted from math lists to boxes by \texttt{tex.web}'s \texttt{mlist\_to\_hlist} (Appendix G of \emph{The TeXbook}), on both paths:
\begin{itemize}
\item \textbf{Appendix G Rules}: Fractions (\texttt{\textbackslash frac}), radicals (\texttt{\textbackslash sqrt}), subscripts/superscripts, delimiters, large operators with limits (\texttt{\textbackslash sum}, \texttt{\textbackslash int}), and over/underbraces are built by the rules of Appendix G from the math fonts' parameters, as pdfTeX builds them.
\item \textbf{Two Passes, as in TeX}: The first pass builds each atom's box; the second inserts the spacing and penalties between atoms (\texttt{tex.web} \S760--\S767).
\item \textbf{Native Math}: In the native job, math atoms come straight from the source and feed the same Appendix G core; no macro expansion runs for the commands it knows.
\end{itemize}

\subsection{Hardware-Grade DEFLATE Engine and L1 Cache Residency}
To compress PDF page streams at over 12,000 pages per second on a single CPU core, \texttt{rushtex} incorporates microarchitectural optimizations targeting Intel/AMD L1 data caches:
\begin{itemize}
\item \textbf{Packed 32 KB AoS Match Table with Epoch Tagging}: The match table is represented as \texttt{table: [u64; 4096]} (exactly 32 KB, fitting 100\% inside CPU L1 data cache with 8 slots per 64-byte cache line). Each entry packs \texttt{(epoch << 40) | (prefix << 16) | pos}. By incrementing the epoch counter between page streams, table zeroing (\texttt{memset}) is eliminated entirely, removing megabytes of L1 cache flushing across multi-page documents.
\item \textbf{Single-Cycle XOR Bitmask Verification}: Slot validity, epoch matching, and 3-byte prefix verification are resolved simultaneously in a single 64-bit operation: \texttt{((entry \^{} expected) \& MASK) == 0}, eliminating multiple branch instructions and memory unpacks in the hottest loop.
\item \textbf{Compile-Time Monomorphized Specialization}: The DEFLATE engine uses Rust const-generics (\texttt{compress\_raw\_inner<const USE\_EPOCH: bool>}) to optimize away epoch branches at compile time, eliminating over 1.6 million branch checks on a 100,000-word document.
\item \textbf{Unified 32-Bit Packed Huffman Tables}: Literal, length, and distance tables (\texttt{LIT\_TABLE}, \texttt{LENGTH\_TABLE}, \texttt{DIST\_TABLE\_2048}) are packed into contiguous 32-bit quadwords (\texttt{code | (bits << 16)}). Exactly 16 entries fit per 64-byte cache line (10 KB total table state), guaranteeing zero L1 cache evictions.
\item \textbf{Single-Call 64-Bit Length+Distance Emission}: \texttt{BitWriter::write\_bits} takes 64-bit inputs. Length and distance Huffman codes are merged into a single word (\texttt{len\_bits | (dist\_bits << len\_count)}) and emitted in one call, cutting bitwriter invocation frequency by 50\%.
\item \textbf{Dual-Literal Batching}: Uncompressible literal sequences are emitted 2 bytes at a time in a single bitwriter transaction.
\item \textbf{Reusable Compressor}: One compressor and its match table serve every stream of the document, so the table is allocated once per job.
\end{itemize}

\subsection{Modular Subsystem Architecture}
The codebase is structured into a few domain modules enabling multiple developers to work concurrently on distinct aspects of the compiler:
\begin{itemize}
\item \textbf{Native job (\texttt{src/engine/engine\_doc.rs})}: The pre-scan, the direct compiler and the typed node builders of guarded direct lowering, for the documents whose every construct is ported.
\item \textbf{TeX engine (\texttt{src/engine/})}: \texttt{tex.web} and pdfTeX ported: the lexer and macro expansion, line breaking (\texttt{engine\_linebreak.rs}), math (\texttt{engine\_mlist.rs}), alignment, the page builder (\texttt{engine\_page.rs}), and the LaTeX format's build and load.
\item \textbf{Data (\texttt{src/data/})}: The generated tables both paths read (fonts, hyphenation, the kernel's and classes' macros, in \texttt{assets/tables/}), built by \texttt{rushtex-gen}.
\item \textbf{Backend (\texttt{src/backend/})}: PDF writing (\texttt{backend\_ship.rs}), Type 1 font subsetting (\texttt{backend\_type1.rs}), PNG and PDF images, and streaming RFC 1951 DEFLATE compression (\texttt{backend\_deflate.rs}).
\item \textbf{Command line (\texttt{src/main.rs})}: The two-path driver: the native job first, the TeX engine when it declines, and \texttt{--watch}.
\item \textbf{Testing framework (\texttt{testing/})}: \texttt{parity-testing} compares every glyph, rule and pixel with pdfLaTeX's output.
\end{itemize}

\section{Diagnostics: Which Path Ran}
With \texttt{RT\_NATIVE\_WHY=1}, \texttt{rushtex} reports which path compiled the document and, when the native job declined, why:

\begin{verbatim}
$ RT_NATIVE_WHY=1 rushtex manual.tex
native job declined: the pre-scan: listings
engine job: 3 runs
[COMPILED] Output file is in manual.pdf, 24 pages in 1.187 seconds
\end{verbatim}

\subsection{Diagnostic Features}
\begin{itemize}
\item \textbf{Decline Reason}: The first construct the native job does not take, as the pre-scan or the running job found it.
\item \textbf{Blocker List}: \texttt{--native-gaps} lists every such construct of a document at once.
\item \textbf{No Silent Third Path}: When the native job declines and no TeX Live installation or cache folder is found, the compiler stops with an error naming the decline reason instead of typesetting approximately.
\end{itemize}

\section{List and Enumeration Geometry}
List geometry is LaTeX's own: the class sets the list dimensions, \texttt{enumitem} changes them, and both paths compute them as pdfLaTeX does.

\subsection{Mathematical Model of List Geometry}
A list environment is governed by six horizontal dimensions:
\begin{itemize}
\item \texttt{leftmargin}: The horizontal offset of the list body from the parent left margin.
\item \texttt{labelwidth}: The nominal width allocated for the marker bounding box.
\item \texttt{labelsep}: The horizontal separation between the marker and the first word of text.
\item \texttt{itemindent}: The first-line indentation of each item relative to \texttt{leftmargin}.
\item \texttt{hangindent}: The hanging indentation applied to subsequent lines.
\item \texttt{listparindent}: Indentation for subsequent paragraphs inside the same item.
\end{itemize}

The horizontal placement of the marker and text satisfies:
\begin{lstlisting}[language=Rust, numbers=left]
let first_line_x = left + left_margin + item_indent;
let marker_x = first_line_x - label_sep - marker_w;
assert!(marker_x >= left); // bounded against margin bleed
\end{lstlisting}

\subsection{Multi-Level Nested Enumeration Test}
Nested enumerations automatically scale their base margins and switch numbering formats across hierarchy levels:

\begin{enumerate}
\item Level 1 Item: Arabic numeral with period (\texttt{1.}, \texttt{2.})
  \begin{enumerate}
  \item Level 2 Item: Lowercase alphabetic in parentheses (\texttt{(a)}, \texttt{(b)})
    \begin{enumerate}
    \item Level 3 Item: Lowercase Roman numeral with period (\texttt{i.}, \texttt{ii.})
    \item Another Level 3 Item demonstrating Roman numbering alignment
    \end{enumerate}
  \item Level 2 Second Item demonstrating depth margin indent
  \end{enumerate}
\item Level 1 Second Item demonstrating return to top-level geometry
\end{enumerate}

\subsection{Multi-Level Nested Itemize Test}
Unordered lists scale bullets across nesting levels:

\begin{itemize}
\item Level 1 Itemize: Standard bullet point (\texttt{\textbullet})
  \begin{itemize}
  \item Level 2 Itemize: En-dash bullet marker (\texttt{--})
    \begin{itemize}
    \item Level 3 Itemize: Asterisk marker (\texttt{*})
    \item Another Level 3 Itemize entry
    \end{itemize}
  \item Level 2 Second Itemize entry
  \end{itemize}
\item Level 1 Second Itemize entry
\end{itemize}

\subsection{Custom Geometry Overrides}
Fine-grained geometry overrides are supported via bracket options:

\begin{enumerate}[labelsep=15pt, leftmargin=35pt, itemindent=5pt]
\item First line indented by 5pt with marker ending exactly 15pt before text.
\item Subsequent lines align at leftmargin (35pt) for clean hanging list typography.
\end{enumerate}

\subsection{Custom Starting Values and Label Formats}
Enumeration sequences can specify initial counter offsets and label formats via bracket options:

\begin{enumerate}[start=3, label=(\alph*)]
\item Third item formatted as alphabetical in parentheses.
\item Fourth item continuing the alphabetical sequence.
\end{enumerate}

Supported formats include Arabic with period (\verb|\arabic*|), parenthesized Arabic (\verb|(\arabic*)|), alphabetical in parentheses (\verb|(\alph*)| or \verb|\alph*|), and uppercase Roman numerals (\verb|\Roman*|).

\subsection{Description Lists and Custom Item Labels}
The \texttt{description} environment typesets terms and definitions with hanging indentation. Each item specifies a term via \verb|\item[Term]|:

\begin{description}
\item[Native job] Pre-scan and direct lowering of the documents it accepts.
\item[TeX engine] \texttt{tex.web} and pdfTeX, run on the LaTeX format for every other document.
\item[Backend] PDF writer with Type 1 font subsetting and DEFLATE compression.
\end{description}

Custom markers can also override default numbering or bullets on single items in standard lists:

\begin{enumerate}
\item First standard numbered item.
\item[(X)] Custom override marker for an exceptional entry.
\item Resumes standard sequence with correct offset.
\end{enumerate}

\subsection{Block Quotations (\texttt{quote} and \texttt{quotation})}
Block quotations indent both the left and right margins symmetrically by 24pt, with symmetric vertical clearance:

\begin{quote}
Simplicity is prerequisite for reliability. A system should be built in the simplest possible manner that satisfies requirements.
\end{quote}

The \texttt{quotation} environment additionally preserves first-line paragraph indentation for multi-paragraph quotations:

\begin{quotation}
Premature optimization is the root of all evil in programming. Yet we should not pass up our opportunities in that critical 3 percent.

A good programmer will not be lulled into complacency by such reasoning, he will be wise to look carefully at the critical code.
\end{quotation}

\section{Typography and Inline Formatting}
Fonts are selected by LaTeX's font selection scheme, and their Type 1 programs are embedded as pdfTeX embeds them:

\begin{itemize}
\item \textbf{Default Body Font (Computer Modern Roman)}: LaTeX's default typeface, as in the body of this manual.
\item \textbf{Bold Face}: Produced using \verb|\textbf{...}| (Computer Modern Bold Extended).
\item \textit{Italic Face}: Produced using \verb|\textit{...}| or \verb|\emph{...}| (Computer Modern Italic).
\item \texttt{Monospace Face}: Produced using \verb|\texttt{...}| or inline \verb|\verb| (Computer Modern Typewriter).
\item \textbf{\textit{Combined Styling}}: Nested bold and italic produces Computer Modern Bold Extended Italic.
\item \textbf{Sans-Serif (Helvetica)}: Activated via \verb|\usepackage{helvet}|, then making the sans-serif family the default: \verb|\renewcommand{\familydefault}{\sfdefault}|.
\item \textbf{Palatino Typeface}: Activated via \verb|\usepackage{palatino}| or \verb|\usepackage{mathpazo}| for elegant book typography.
\item \textbf{Latin Modern}: The Computer Modern successor, activated via \verb|\usepackage{lmodern}|.
\item \textbf{Math and Dingbat Symbols}: STEM symbols like \verb|\alpha|, \verb|\beta|, \verb|\infty| from the Computer Modern math fonts and the AMS fonts (\verb|\usepackage{amssymb}|), and dingbats like checkmarks via \verb|\usepackage{pifont}| (ZapfDingbats).
\item \textbf{Special Character Escapes}: Escaped symbols for \verb|\%|, \verb|\$|, \verb|\&|, \verb|\#|, \verb|\_|, \verb|\{|, and \verb|\}|.
\item \textbf{Text Entity Commands}: \verb|\textbackslash{}| emits \textbackslash{}, \verb|\textasciitilde{}| emits \textasciitilde{}, and \verb|\textasciicircum{}| emits \textasciicircum{}.
\end{itemize}

\subsection{Selective PDF Resource Pruning}
To minimize generated PDF file sizes and reduce reader decode times, \texttt{rushtex} writes only the fonts a document uses, as pdfTeX does:
\begin{itemize}
\item Before emitting a page's \texttt{/Resources} dictionary, the backend records which fonts the page uses, and the dictionary names only those.
\item Each Type 1 font is subset to the glyphs the document uses before it is embedded.
\item Font programs come from the TeX Live installation when one is found, otherwise from the copies the binary carries.
\end{itemize}

\subsection{Microtypography and Page Breaking}
Margin kerning and font expansion are pdfTeX's, set up by the \texttt{microtype} package; page breaking is TeX's:
\begin{itemize}
\item \textbf{Optical Margin Alignment}: With \verb|\usepackage{microtype}|, punctuation marks (such as hyphens, periods, commas, and quotes) protrude into the margin by the amounts of \texttt{microtype}'s configuration, as pdfTeX computes them.
\item \textbf{Font Expansion}: pdfTeX's \verb|\pdfadjustspacing| stretches or shrinks glyphs within \texttt{microtype}'s limits, and line breaking takes it into account.
\item \textbf{Club and Widow Penalties}: \verb|\clubpenalty| and \verb|\widowpenalty| (150 in LaTeX) weigh a page break after a paragraph's first line or before its last, as TeX's page builder does.
\end{itemize}

\subsection{Paragraph Formatting and First-Line Indents}
Standard LaTeX paragraph control commands are supported as LaTeX defines them:
\begin{itemize}
\item \verb|\setlength{\parindent}{18pt}|: Sets global paragraph first-line indent.
\item \verb|\indent|: Explicitly forces first-line indentation on a paragraph.
\item \verb|\noindent|: Suppresses first-line indentation for the following paragraph.
\item \verb|\hangindent 24pt| and \verb|\hangafter 1|: Knuth-style hanging indentation.
\item \verb|\setlength{\parskip}{6pt}|: Adjusts inter-paragraph vertical spacing.
\item \verb|\hspace{15pt}| and \verb|\hspace*{15pt}|: Inserts an explicit horizontal spacing skip between inline words.
\end{itemize}

\section{Code Listings and Verbatim}
Both raw verbatim blocks and styled numbered listings (\texttt{listings}) are supported; \texttt{listings} is what sends this manual to the TeX engine:

\begin{verbatim}
// Raw verbatim block preserving exact whitespace and symbols:
fn compute_checksum(data: &[u8]) -> u32 {
    let mut s1: u32 = 1;
    let mut s2: u32 = 0;
    for &b in data {
        s1 = (s1 + b as u32) % 65521;
        s2 = (s2 + s1) % 65521;
    }
    (s2 << 16) | s1
}
\end{verbatim}

\begin{lstlisting}[language=Rust, numbers=left]
pub fn fast_add(a: u64, b: u64) -> u64 {
    a.wrapping_add(b)
}
\end{lstlisting}

Code listings feature automatic tab expansion to four spaces, optional line numbering in a dedicated gutter, a light background panel, and an accent bar.

\subsection{Multi-Page Streaming: The \texttt{longtable} Environment}
When tables span beyond a single page, the standard \texttt{tabular} environment overflows past the bottom margin. The \texttt{longtable} environment solves this by streaming rows across arbitrary page boundaries:
\begin{itemize}
\item \verb|\endfirsthead|: Marks the header rows displayed exclusively at the top of the very first page.
\item \verb|\endhead|: Marks the repeating header rows re-emitted at the top of every subsequent page after a page break.
\item \verb|\endfoot|: Marks the footer rows emitted at the bottom of each page before continuation.
\item \textbf{Dynamic Row Balancing}: Rows are never split across baselines; pagination triggers cleanly at row boundaries.
\end{itemize}

\section{Document Indexing and Navigation Subsystem}
Document catalogs and navigation structures---such as Table of Contents (\texttt{\textbackslash tableofcontents}), List of Figures (\texttt{\textbackslash listoffigures}), and List of Tables (\texttt{\textbackslash listoftables})---are typeset by LaTeX's own commands (\verb|\@starttoc|, \verb|\contentsline|, \verb|\@dottedtocline|), so their indentation, leaders and page numbers are pdfLaTeX's.

\subsection{Where the Entries Come From}
Each list is made from what the document's sectioning and caption commands record:
\begin{itemize}
\item \verb|\section|, \verb|\subsection| and \verb|\subsubsection| add \texttt{toc} entries with their numbers.
\item \verb|\caption| in a \texttt{figure} or \texttt{table} adds a \texttt{lof} or \texttt{lot} entry.
\item \verb|\label| records the current number and page for \verb|\ref| and \verb|\pageref|.
\item \verb|\tableofcontents| typesets the \texttt{toc} entries with \verb|\l@section| and its kin.
\end{itemize}

\subsection{In-Memory Resolution}
LaTeX writes this metadata to auxiliary files (e.g. \texttt{.toc}, \texttt{.lot}, \texttt{.lof}) and needs several runs. \texttt{rushtex} writes no auxiliary files:
\begin{enumerate}
\item \textbf{Native Job}: Entries, labels and page numbers are kept in memory and resolved within its one pass.
\item \textbf{TeX Engine}: The job runs as many times as LaTeX would need (three for this manual), with the auxiliary files kept in memory between runs.
\item \textbf{Same Output}: Either way the PDF is the one pdfLaTeX writes on its final run.
\end{enumerate}

\subsection{Shipping Pages Out}
A finished page is shipped out as pdfTeX ships it (\texttt{tex.web} \S592 and pdfTeX's PDF backend):
\begin{itemize}
\item Characters become text-showing operators in the page's content stream, with the font's encoding.
\item Rules become filled rectangles.
\item Images included with \verb|\includegraphics| become image XObjects (an included PDF becomes a form XObject).
\item Each content stream is compressed with DEFLATE before it is written.
\end{itemize}

\subsection{Memory Use}
Following strict hardware cache and memory locality invariants, \texttt{rushtex} keeps peak resident RAM low on large documents:
\begin{itemize}
\item \textbf{Arena Nodes}: Nodes live in one arena with side tables, and lists being built sit back to back in one growing buffer, so building a box allocates nothing per box.
\item \textbf{Page at a Time}: Each page is written to the PDF when it is shipped out, and its nodes are freed.
\end{itemize}

\section{Mathematical Typography and Equation Reference (\texttt{math})}
The \texttt{rushtex} mathematical typesetting subsystem implements the mathematical layout specified in TeX Appendix G (\emph{The TeXbook} by Donald Knuth) as \texttt{tex.web} computes it. This section serves a dual purpose: it acts as a comprehensive reference guide explaining how every equation type is defined, parsed, and typeset, while functioning as a rigorous visual specimen suite spanning major branches of theoretical physics and modern mathematics.

\subsection{Mathematical Environments and Equation Types}
Mathematical typesetting in \texttt{rushtex} is strictly partitioned into distinct rendering environments, each tailored for specific structural, geometric, and semantic requirements.

\subsubsection{Inline Mathematics (\texttt{\$...} and \texttt{\textbackslash(...\textbackslash)})}
Inline formulas appear within running paragraph prose. In this mode, the layout engine selects \emph{Text Style} ($T$) or \emph{Cramped Text Style} ($T'$), enforcing tight vertical bounds to prevent uneven inter-line spacing:
\begin{itemize}
\item Operators (such as $\sum$ or $\int$) place limits horizontally as subscripts and superscripts rather than vertically above and below.
\item Built-up fractions are compressed, and inter-atom spacing is slightly reduced.
\item Examples: The mass-energy equivalence $E = mc^2$, Euler's identity $e^{i\pi} + 1 = 0$, the de Broglie wavelength $\lambda = \frac{h}{p}$, and the Heisenberg uncertainty relation $\Delta x \, \Delta p \ge \frac{\hbar}{2}$.
\end{itemize}

\subsubsection{Unnumbered Display Mathematics (\texttt{\textbackslash[...\textbackslash]} and \texttt{\$\$...})}
Display equations are rendered as independent blocks centered horizontally across the text column. In this mode, the engine selects \emph{Display Style} ($D$):
\begin{itemize}
\item Fractions, radicals, and large operators utilize expanded vertical clearances and full-sized glyphs.
\item Operators automatically place their limits directly above and below the nucleus.
\end{itemize}
\[
\int_{-\infty}^{\infty} e^{-x^2} \, \mathrm{d}x = \sqrt{\pi}
\]

\subsubsection{Numbered Equation Environments (\texttt{equation} and \texttt{equation*})}
The \texttt{equation} environment centers the formula horizontally while automatically generating a right-aligned equation number enclosed in parentheses. The counter increments monotonically across the document:
\begin{equation}
i \hbar \frac{\partial}{\partial t} \Psi(\mathbf{r}, t) = \left( -\frac{\hbar^2}{2m} \nabla^2 + V(\mathbf{r}, t) \right) \Psi(\mathbf{r}, t)
\end{equation}
The starred variant \texttt{equation*} suppresses the equation number while preserving identical display-style geometry:
\begin{equation*}
\mathcal{L} = \bar{\psi} (i \gamma^\mu D_\mu - m) \psi - \frac{1}{4} F_{\mu\nu} F^{\mu\nu}
\end{equation*}

\subsubsection{Multi-Line Aligned Systems (\texttt{align} and \texttt{align*})}
The \texttt{align} and \texttt{align*} environments typeset multi-line derivations with horizontal alignment anchored at relation symbols (typically \verb|&=|). Each line in \texttt{align} receives an individual equation number unless suppressed:
\begin{align}
\nabla \cdot \mathbf{E} &= \frac{\rho}{\varepsilon_0} \\
\nabla \cdot \mathbf{B} &= 0 \\
\nabla \times \mathbf{E} &= -\frac{\partial \mathbf{B}}{\partial t} \\
\nabla \times \mathbf{B} &= \mu_0 \mathbf{J} + \mu_0 \varepsilon_0 \frac{\partial \mathbf{E}}{\partial t}
\end{align}
Unnumbered alignments use \texttt{align*}:
\begin{align*}
\oint_{\partial S} \mathbf{E} \cdot \mathrm{d}\mathbf{l} &= -\frac{\mathrm{d}}{\mathrm{d}t} \iint_S \mathbf{B} \cdot \mathrm{d}\mathbf{S} \\
\oint_{\partial S} \mathbf{B} \cdot \mathrm{d}\mathbf{l} &= \mu_0 I_{\text{enc}} + \mu_0 \varepsilon_0 \frac{\mathrm{d}}{\mathrm{d}t} \iint_S \mathbf{E} \cdot \mathrm{d}\mathbf{S}
\end{align*}

\subsubsection{Centered Multi-Line Groups (\texttt{gather} and \texttt{gather*})}
The \texttt{gather} environment typesets multiple formulas where each line is individually centered without column alignment:
\begin{gather}
H = \sum_{i=1}^n \frac{p_i^2}{2m} + \sum_{i<j} V(r_{ij}) \\
\dot{q}_i = \frac{\partial H}{\partial p_i}, \quad \dot{p}_i = -\frac{\partial H}{\partial q_i}
\end{gather}

\subsubsection{Long Splitting Equations (\texttt{multline})}
When an equation is too long to fit across a single column width, the \texttt{multline} environment breaks it across several lines: the first line is left-aligned, the final line is right-aligned, and intermediate lines are centered:
\begin{multline}
f(x) = a_0 + a_1 x + a_2 x^2 + a_3 x^3 + a_4 x^4 + a_5 x^5 + a_6 x^6 \\
+ b_1 \sin(x) + b_2 \sin(2x) + b_3 \sin(3x) + b_4 \sin(4x) \\
+ c_1 \cos(x) + c_2 \cos(2x) + c_3 \cos(3x) + c_4 \cos(4x)
\end{multline}

\subsection{TeX Appendix G Architectural Engine and Mathematical Spacing}
The \texttt{rushtex} mathematical typesetting subsystem implements the placement rules of TeX Appendix G as \texttt{tex.web} does (\S719--\S767):

\begin{itemize}
\item \textbf{Mathematical Axis Centering}: All fraction rules, relation operators ($=$, $\le$, $\approx$), and extensible delimiters are symmetrically centered on the font's mathematical axis ($\sigma_{22}$), eliminating vertical drift between formulas.
\item \textbf{The Eight Atom Kinds}: Every mathematical node is categorized into: \texttt{Ord} (ordinary symbol), \texttt{Op} (large operator), \texttt{Bin} (binary operator), \texttt{Rel} (relation), \texttt{Open} (opening fence), \texttt{Close} (closing fence), \texttt{Punct} (punctuation), and \texttt{Inner} (enclosed sub-formula).
\item \textbf{Math Lists as in \texttt{tex.web}}: A formula is a list of noads, one per atom, converted to boxes and glue by \texttt{mlist\_to\_hlist} (\S726).
\item \textbf{Two Passes}: The first pass builds each atom's box and fixes its class; the second inserts inter-atom spacing and penalties (\S760--\S767).
\item \textbf{Authoritative Font Parameters (\texttt{FontDimen22})}: Clearances, rule thicknesses ($\xi_8$), numerator shifts ($\sigma_8, \sigma_9$), denominator drops ($\sigma_{11}, \sigma_{12}$), and operator limit gaps ($\xi_9 \dots \xi_{12}$) are read from the TFM parameters of math families 2 and 3, never estimated.
\item \textbf{Spacing Table}: Typographic spacing between any adjacent pair of atoms comes from TeX's spacing table (\S764), giving canonical math spacing: thin space ($3\,\text{mu}$), medium space ($4\,\text{mu}$), and thick space ($5\,\text{mu}$), with display-style natural glue expansion.
\item \textbf{Rule 5 Boundary Normalization}: Binary operators (\texttt{Bin}) positioned at expression boundaries or directly following another operator (e.g., unary minus in $-x$ or $x = -y$) are dynamically converted to ordinary atoms (\texttt{Ord}), preventing erroneous gap expansion.
\item \textbf{Italic Correction and Overhang Shielding}: Slanted characters (such as $f$, $j$, $y$) project an italic correction to superscripts and opening delimiters to eliminate visual collisions (e.g., $f(x)$ vs. $x(t)$), while subscripts remain tucked underneath.
\end{itemize}

\subsection{Comprehensive Physics Showcase}
This section presents foundational formulations from major branches of theoretical and applied physics, typeset by \texttt{rushtex}.

\subsubsection{Classical Mechanics and Analytical Dynamics}
In Lagrangian mechanics, the dynamics of a system with generalized coordinates $q_i$ and generalized velocities $\dot{q}_i$ are governed by the action principle $\delta S = 0$, where $S = \int \mathcal{L} \, \mathrm{d}t$:
\begin{equation}
\frac{\mathrm{d}}{\mathrm{d}t} \left( \frac{\partial \mathcal{L}}{\partial \dot{q}_i} \right) - \frac{\partial \mathcal{L}}{\partial q_i} = 0, \quad i = 1, \dots, n
\end{equation}
Under the Legendre transformation $p_i = \frac{\partial \mathcal{L}}{\partial \dot{q}_i}$, the Hamiltonian $\mathcal{H}(q_i, p_i, t) = \sum_{i=1}^n p_i \dot{q}_i - \mathcal{L}$ yields Hamilton's canonical equations:
\begin{equation}
\dot{q}_i = \frac{\partial \mathcal{H}}{\partial p_i}, \quad \dot{p}_i = -\frac{\partial \mathcal{H}}{\partial q_i}
\end{equation}
The time evolution of any dynamical observable $A(q, p, t)$ is given by the Poisson bracket:
\begin{equation}
\frac{\mathrm{d}A}{\mathrm{d}t} = \{A, \mathcal{H}\} + \frac{\partial A}{\partial t}, \quad \{A, B\} = \sum_{i=1}^n \left( \frac{\partial A}{\partial q_i}\frac{\partial B}{\partial p_i} - \frac{\partial A}{\partial p_i}\frac{\partial B}{\partial q_i} \right)
\end{equation}

\subsubsection{Classical Electrodynamics and Field Theory}
Maxwell's equations in microscopic differential form describe the coupling between electric and magnetic fields:
\begin{align}
\nabla \cdot \mathbf{E} &= \frac{\rho}{\varepsilon_0} \\
\nabla \cdot \mathbf{B} &= 0 \\
\nabla \times \mathbf{E} &= -\frac{\partial \mathbf{B}}{\partial t} \\
\nabla \times \mathbf{B} &= \mu_0 \mathbf{J} + \mu_0 \varepsilon_0 \frac{\partial \mathbf{E}}{\partial t}
\end{align}
In relativistic 4-vector notation, the electromagnetic field strength tensor $F^{\mu\nu} = \partial^\mu A^\nu - \partial^\nu A^\mu$ unifies these relations:
\begin{equation}
\partial_\mu F^{\mu\nu} = \mu_0 J^\nu, \quad \partial_\mu \tilde{F}^{\mu\nu} = 0
\end{equation}
The electromagnetic stress-energy tensor $T^{\mu\nu}$ and the Lorentz force density $f^\mu$:
\begin{equation}
T^{\mu\nu} = \frac{1}{\mu_0} \left( F^{\mu\alpha} F^\nu{}_\alpha - \frac{1}{4} \eta^{\mu\nu} F_{\alpha\beta} F^{\alpha\beta} \right), \quad f^\mu = \partial_\nu T^{\mu\nu} = F^{\mu\nu} J_\nu
\end{equation}

\subsubsection{Quantum Mechanics and Quantum Field Theory}
The time-dependent Schrödinger equation for a non-relativistic quantum particle in three dimensions:
\begin{equation}
i \hbar \frac{\partial}{\partial t} \Psi(\mathbf{r}, t) = \left( -\frac{\hbar^2}{2m} \nabla^2 + V(\mathbf{r}) \right) \Psi(\mathbf{r}, t)
\end{equation}
The relativistic Dirac equation for spin-$1/2$ fermions:
\begin{equation}
\left( i \hbar \gamma^\mu \partial_\mu - mc \right) \psi = 0
\end{equation}
where the $4 \times 4$ Dirac gamma matrices satisfy the Clifford algebra anticommutation relation:
\begin{equation}
\{\gamma^\mu, \gamma^\nu\} = \gamma^\mu \gamma^\nu + \gamma^\nu \gamma^\mu = 2 \eta^{\mu\nu} I_4
\end{equation}
The canonical commutation relations in quantum mechanics:
\begin{equation}
[\hat{x}_j, \hat{p}_k] = i \hbar \delta_{jk}, \quad [\hat{L}_x, \hat{L}_y] = i \hbar \hat{L}_z
\end{equation}
The quantum harmonic oscillator in terms of creation ($a^\dagger$) and annihilation ($a$) ladder operators:
\begin{equation}
\hat{H} = \hbar \omega \left( a^\dagger a + \frac{1}{2} \right), \quad [a, a^\dagger] = 1, \quad a |n\rangle = \sqrt{n} |n-1\rangle, \quad a^\dagger |n\rangle = \sqrt{n+1} |n+1\rangle
\end{equation}
The Feynman path integral formulation of quantum transition amplitudes:
\begin{equation}
\langle x_f, t_f | x_i, t_i \rangle = \int \mathcal{D}[x(t)] \, \exp\left( \frac{i}{\hbar} \int_{t_i}^{t_f} \mathcal{L}(x, \dot{x}) \, \mathrm{d}t \right)

\subsubsection{General Relativity and Cosmology}
Einstein's field equations relate spacetime curvature to the distribution of mass and energy:
\begin{equation}
G_{\mu\nu} + \Lambda g_{\mu\nu} = \frac{8 \pi G}{c^4} T_{\mu\nu}, \quad G_{\mu\nu} \equiv R_{\mu\nu} - \frac{1}{2} R g_{\mu\nu}

The Riemann curvature tensor and Christoffel connection coefficients:
\begin{equation}
\Gamma^\mu_{\alpha\beta} = \frac{1}{2} g^{\mu\sigma} \left( \partial_\alpha g_{\beta\sigma} + \partial_\beta g_{\alpha\sigma} - \partial_\sigma g_{\alpha\beta} \right)
\end{equation}
\begin{equation}
R^\rho{}_{\sigma\mu\nu} = \partial_\mu \Gamma^\rho_{\nu\sigma} - \partial_\nu \Gamma^\rho_{\mu\sigma} + \Gamma^\rho_{\mu\lambda} \Gamma^\lambda_{\nu\sigma} - \Gamma^\rho_{\nu\lambda} \Gamma^\lambda_{\mu\sigma}
\end{equation}
The geodesic equation for test particles in curved spacetime:
\begin{equation}
\frac{\mathrm{d}^2 x^\mu}{\mathrm{d}\tau^2} + \Gamma^\mu_{\alpha\beta} \frac{\mathrm{d}x^\alpha}{\mathrm{d}\tau} \frac{\mathrm{d}x^\beta}{\mathrm{d}\tau} = 0
\end{equation}
The Schwarzschild metric line element describing the vacuum geometry outside a spherical mass $M$:
\begin{equation}
\mathrm{d}s^2 = -\left( 1 - \frac{2GM}{c^2 r} \right) c^2 \mathrm{d}t^2 + \left( 1 - \frac{2GM}{c^2 r} \right)^{-1} \mathrm{d}r^2 + r^2 (\mathrm{d}\theta^2 + \sin^2\theta \, \mathrm{d}\phi^2)
\end{equation}
In modern cosmology, the Friedmann equations describe the expansion of a homogeneous and isotropic universe with scale factor $a(t)$:
\begin{equation}
\left( \frac{\dot{a}}{a} \right)^2 = \frac{8\pi G}{3} \rho - \frac{k c^2}{a^2} + \frac{\Lambda c^2}{3}, \quad \frac{\ddot{a}}{a} = -\frac{4\pi G}{3}\left( \rho + \frac{3p}{c^2} \right) + \frac{\Lambda c^2}{3}

\subsubsection{Complex Analysis and Residue Calculus}

\frac{\partial u}{\partial x} = \frac{\partial v}{\partial y}, \quad \frac{\partial u}{\partial y} = -\frac{\partial v}{\partial x}

\subsubsection{Number Theory and the Riemann Zeta Function}
The Riemann zeta function $\zeta(s)$ defined on the half-plane $\operatorname{Re}(s) > 1$ by Dirichlet series and Euler product:

\subsubsection{Differential Geometry and Stokes' Theorem}
The generalized Stokes' theorem on smooth oriented manifolds:
\begin{equation}
\int_{\partial \Omega} \omega = \int_\Omega \mathrm{d}\omega

where $\omega$ is a differential $(k-1)$-form and $\mathrm{d}\omega$ is its exterior derivative.
The Gauss-Bonnet theorem connecting total Gaussian curvature $K$ and geodesic curvature $k_g$ to the topological Euler characteristic $\chi(M)$:
\begin{equation}
\iint_M K \, \mathrm{d}A + \oint_{\partial M} k_g \, \mathrm{d}s = 2\pi \chi(M)
\end{equation}

\subsubsection{Probability Theory and Multivariate Statistics}
The probability density function of a $k$-dimensional multivariate normal distribution:
\begin{equation}
f(\mathbf{x}) = \frac{1}{(2\pi)^{k/2} |\boldsymbol{\Sigma}|^{1/2}} \exp\left( -\frac{1}{2} (\mathbf{x} - \boldsymbol{\mu})^T \boldsymbol{\Sigma}^{-1} (\mathbf{x} - \boldsymbol{\mu}) \right)
\end{equation}
Bayes' theorem for continuous probability density distributions:
\begin{equation}
p(\theta | \mathbf{x}) = \frac{p(\mathbf{x} | \theta) \, p(\theta)}{\int p(\mathbf{x} | \theta') \, p(\theta') \, \mathrm{d}\theta'}
\end{equation}
The Central Limit Theorem for independent and identically distributed random variables:
\begin{equation}
\lim_{n \to \infty} P\left( \frac{\sum_{i=1}^n X_i - n\mu}{\sigma \sqrt{n}} \le z \right) = \frac{1}{\sqrt{2\pi}} \int_{-\infty}^z e^{-t^2/2} \, \mathrm{d}t = \Phi(z)
\end{equation}

\section{Command-Line Interface (CLI)}
The \texttt{rushtex} executable provides intuitive invocation modes:

\begin{lstlisting}[language=bash]
# Compile a TeX document to PDF
rushtex document.tex -o output.pdf

# Recompile whenever the file changes
rushtex --watch document.tex

# Say which path ran, and why the native job declined
RT_NATIVE_WHY=1 rushtex document.tex

# List everything the native job does not take yet
rushtex document.tex --native-gaps
\end{lstlisting}

Upon completion, \texttt{rushtex} reports the output file, the page count and the wall-clock time:

\begin{verbatim}
$ rushtex document.tex
[COMPILED] Output file is in document.pdf, 10 pages in 0.002 seconds
\end{verbatim}

\section{Programmatic Rust API}
For embedding typesetting inside web servers or cloud functions, the library exposes the native job as \texttt{engine::engine\_doc::run}; a document it declines needs the TeX engine, which the command line (\texttt{src/main.rs}) runs:

\begin{lstlisting}[language=Rust, numbers=left]
use rushtex::engine::engine_doc;

fn main() {
    let src = "\\documentclass{article}\\begin{document}Hello!\\end{document}";

    // The job's date (Unix seconds), for \today
    let now = engine_doc::run_date();

    // The native job: the PDF, or why it declined
    match engine_doc::run(src, now, None) {
        Ok(out) => println!("{} pages", out.pages),
        Err(why) => eprintln!("native job declined: {why}"),
    }
}
\end{lstlisting}

\section{Summary}
The \texttt{rushtex} engine produces the PDF pdfLaTeX produces, natively where its pre-scan accepts a document and on the ported TeX engine otherwise, with strict memory safety.
