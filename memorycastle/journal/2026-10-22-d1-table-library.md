# D1: the table library (perfect hash, SoA columns, CSR, bitsets) and its one blob format
Author: abhi+claude | Date: 2026-10-22
Files: `src/data/data_mod.rs`, `src/data/data_blob.rs`, `src/data/data_phf.rs`, `src/data/data_csr.rs`, `src/data/data_bits.rs`, `src/backend/backend_hash.rs`, `src/lib.rs`, `Cargo.toml`, `src/engine/engine_run.rs`, `memorycastle/journal/progress.md`

## Context
Pillars 2 and 3 (`progress.md`) need static tables that are generated once, read in place and touched only on demand. This covers command names, packages, fonts and `.fd` entries. D1 is the shared library. D2 (`rushtex-gen`) fills it, D3/D4 query it, and P1 is its first consumer. Loader structures: `2026-10-22-document-needs-measure.md`; spec §6b.

## Decision
- **Module.** `src/data/` (`data_*` files); `tables` is already the tabular module.
  - The reader side is product code: std only, no `std::fs` (wasm), and it builds without `oracle`.
  - Builders sit behind `cfg(any(test, feature = "gen"))`, so construction never ships in the product binary.
- **One blob format.** One format serves `include_bytes!` in the binary, the oracle and tests: little-endian sections behind a header of offsets and lengths, read in place from `&[u8]` with no parse and no copy. No Rust source arrays (they would be a second format).
- **Hash.** `backend_hash`'s folded multiply (`fold_mul`), one 64-bit hash per key, split into bucket, slot and fingerprint bits. It is bit-identical at generation and at run time on every target.
- **Perfect hash (`data_phf`).** Bucket displacement with `u16` pilots, about 4 keys per bucket, slots at load factor 0.98 or below, and a fixed seed retried until a build succeeds.
  - A query reads one pilot (2 bytes), then one slot word (`u32`: a 24-bit ID and an 8-bit fingerprint).
  - On a fingerprint match it compares the name bytes (`offsets[id]..offsets[id+1]` in the name blob). The fingerprint rejects 255 of every 256 misses without touching the blob, and the byte comparison keeps hits exact (pillar 5).
- **SoA columns by ID.** These are slices of `u8`/`u16`/`u32` in the blob.
- **CSR (`data_csr`).** `offsets[n+1]` plus `ids`; `row(i)` returns `&[u32]`. `closure` is a BFS into a bitset with a caller-owned stack, so nothing is allocated per call.
- **Bitsets (`data_bits`).** `[u64]` words with test, set, union, difference and iteration. `loaded` and `needs` are arrays by ID, so they can be checkpointed and diffed per block (pillar 4). Everything else is a read-only slice.

## Rejected
- **XOR or binary fuse filter plus a separate hash.** That costs two structures and one more cache miss; the slot fingerprint does the filter's job.
- **A minimal perfect hash (load factor 1).** Its last singleton buckets often find no free slot within `u16` pilots. 2% spare slots make construction reliable and cost 2% of one `u32` column.
- **`std::collections::hash_map::DefaultHasher`.** Its output is not guaranteed stable across Rust versions, and tables generated by one build are read by another.
- **Roaring bitmaps in D1.** Their consumers are D3's per-block needs and P8. They come with D3, with only the containers and operations D3 uses.
- **Generated Rust arrays.** They are a second table format and slow to compile.

## Measured
- Real key set: the LaTeX format's 28,960 control-sequence names (`RT_NAMES` of `format_smoke`, test `phf_real_names`). Built and checked in 8.7 ms.
  - Pilots 14.5 KB, slots 118 KB, offsets 116 KB, name bytes 753 KB: 68.7 bits per name beyond the names.
  - LaTeX3 names are long (26 bytes on average), so the name blob dominates.
- Lookup, `phf.get` against `std::HashMap<&[u8], u32>`, same names, release build on the M5:
  - hit 17.1 ns against 26.1 ns;
  - miss 12.5 ns against 23.5 ns (a miss mostly stops at the fingerprint).
- Per hit it touches one pilot, one slot word, two offsets and the name bytes; per miss, a pilot and a slot word.
- Gate: unit tests (blob round trip and corrupt input refused, bitset operations, CSR closure, a 30k-name set, edge cases, duplicate detection); clippy clean with and without `oracle`. The wasm32 build is not checked locally (target not installed); the readers use no `std::fs`.
