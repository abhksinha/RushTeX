# D2 (registry): every pinned package and class, loaded by LaTeX, as a generated table
Author: abhi+claude | Date: 2026-10-22
Files: `src/data/data_pkgs.rs`, `src/data/data_mod.rs`, `src/bin/rushtex_gen.rs`, `assets/tables/pkgs.rtdb`, `.github/workflows/ci.yml`

## Context
D2's third slice. The D3 pre-scan needs to map a document's command names to the packages that define them, and the files each package loads, so it can take the closure. F1's fallback decision needs to know which packages exist. The P-phase port needs each package's surface: options and commands. This is built in §3a's storage form, like the fonts and NFSS slices.

## Decision
- **Evaluate, don't parse** (as for NFSS). `rushtex-gen pkgs` loads each of the 249 pinned `.sty`/`.cls` files on the LaTeX format: a package on `article`, a class as the class. It records:
  - **direct loads**, from LaTeX's `file/before` and `file/after` hooks with `\CurrentFile`, so the nesting gives parent and child;
  - **declared options**, by wrapping `\@declareoption`;
  - **defined commands**: control sequences whose meaning differs from the same run without the file (read from the engine's `eqtb` in `inspect`).
- **What counts as a package's own command:**
  - drop the commands of the registered files it loads, directly or not, so each command is attributed where it is defined (`\includegraphics` to `graphics.sty`, not `graphicx.sty`);
  - drop LaTeX's bookkeeping, measured: names changed by at least half of all loads (40 names: `@currname`, `reserved@a`, the file stacks), plus per-file names (`ver@x.sty`, `ds@…`);
  - **keep only letter-only names**, which is what a document can write without `\makeatletter`. Internal names (`@`, expl3's `_` and `:`, encoding-prefixed text commands) reach a document only through code that redefines internals, and that takes the F1 fallback. This cut 60,539 names (2.26 MB) to 9,976 (328 KB).
- **Layout:**
  - a perfect hash of file names, with registered files first;
  - CSR rows for loads and options;
  - a perfect hash of command names with a CSR row of defining packages, so a pre-scan lookup is one probe and one contiguous row;
  - options in one deduplicated string pool.
- **Self-check:** every package's name, loads, options and commands are read back from the table and compared with the recorded run. Regeneration is byte-identical, also from moved paths. CI regenerates it with the other two blobs.

## Rejected
- **Recording every changed name:** 2.26 MB, mostly internals no document writes.
- **Attributing transitive definitions to the top package:** `hyperref` would own `keyval`'s commands, and the pre-scan could not tell which file actually provides a command.
- **A hand-written bookkeeping list:** it would drift between kernel releases. The frequency rule measures it from the runs.

## Measured
- 249 packages and classes, 286 files (37 of them `.cfg`, `.def`, `.clo` or `.fd` that registered files load), 9,976 commands; `assets/tables/pkgs.rtdb` is 327,548 bytes.
- Largest surfaces: `hyperref` 2,780 (mostly PU text commands), `scrartcl` 1,438, `pgf` 1,304, `pgfcore` 565, `IEEEtran` 363.
- 12 files fail on their own because they need a parent loaded first: `lstlang1–3`, `lstmisc`, `lstpatch` (listings), `hypcap` (hyperref), `ltcaption` (longtable), `fcprefix` and `fcnumparser` (fmtcount's helpers), `pauldoc`, and pgf's compatibility files. Their parents' loads record them as children.
- Generation: 5.9 s for 251 engine runs.
- Tests: 350 pass; clippy clean with `--all-targets`, without `oracle`, and with `gen` and `--all-targets`.

## Open
- Key-value options (`geometry`, `graphicx` keys, `kvoptions`, `l3keys`) are not recorded; only `\DeclareOption` options are. P6 adds them per ported package, from its keys.
- Package popularity order: it needs per-document load lists over A3's larger sample. Until then IDs are in name order.
- Class (a–e) categorisation and class parameters belong to P5's class tables (`ClassParams`, generated by oracle runs per option set).
