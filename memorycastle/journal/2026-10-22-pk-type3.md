# Bitmap (PK) fonts as Type 3 fonts
Author: abhi+claude | Date: 2026-10-22
Files: `src/backend/backend_pk.rs`, `src/backend/backend_ship.rs`, `src/backend/backend_pdftex.rs`, `src/backend/backend_mod.rs`, `src/engine/engine_ship.rs`, `src/engine/engine_page.rs`, `scripts/parity/corpus/bicaption.tex`, `scripts/parity/corpus/ltcaption.tex`, `scripts/parity/corpus/captiondoc.cls`, `scripts/parity/corpus/algorithmicx.tex`, `scripts/parity/corpus/algorithms.tex`, `scripts/parity/corpus/listings.tex`

## Context
Batch 4 item. bicaption.dtx shows one glyph of `ifsym10`, a Metafont-only font: pdfTeX finds
no map entry and embeds the PK bitmaps as a Type 3 font (writet3.c `writepk`).

## Decision
- New `backend_pk.rs`: pkin.c `readchar`/`unpack` (run-length and bitmap rasters, huge
  counts, repeat rows), only the used characters unpacked, the rest skipped by packet
  length. pktype.web: `pl` counts from the `tfm` field, after `cc` (first reading it from
  the length field ran past the packet). kpathsea `magstep_fix` for the file's dpi;
  `get_pk_font_scale`, `pk_char_width`, `getpkcharwidth` as writet3.c.
- `mapfile.c isscalable`: a font is scalable when `pdftex.map` names it (or it is one of our
  built-in programs). The map's TFM names are kept as a sorted `Vec<u64>` of FNV-1a hashes,
  read once at the first shipout (`backend_ship::map_names`); lookup is a binary search, the
  map text is not kept. Per font the PK scale is fixed at the first shipout after its load
  (`Machine::classify_fonts`), 0 for scalable.
- A bitmap font shares its object with no other size (`pdf_init_font`), and its advance in
  the content stream is `getpkcharwidth` (`TextState::pk_scale`). An expanded copy takes
  its base's class (its own name has no map entry; the first try broke wrapfig-doc).
- The characters a page uses are recorded per shared font as a 256-bit set
  (`Page::font_used`, pdfTeX's `pdf_char_marked`); the Type 3 font holds exactly those, with
  `FirstChar`/`LastChar` from the set, `/a<code>` names and `.notdef` runs as writet3.c.
  Widths, encoding and CharProcs are inline in the font dictionary; each glyph procedure is
  its own deflated stream, byte-identical to pdfTeX's (md5 checked).

## Rejected
- Keeping the map as a `HashMap<&str,&str>` across the run: the hashes are 8 bytes a name
  and need no borrow of the map text.
