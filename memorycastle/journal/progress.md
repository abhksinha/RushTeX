## Decision
### Standing rules (every item is checked against them)
- **No garbage collection.** Memory is owned and freed at known points (pools, regions, free lists; §6a of the spec). No tracing, compaction or moving of live data.
- **No hot loops.** Every surviving per-token, per-node or per-line loop is measured with `scripts/profile_doc.py` and justified in its module's comments.
- **Structures by access pattern.** Every table is SoA where a phase reads one field across many records, and AoS where a record is read whole; the choice is written next to the type.
- **Borrow, don't copy.** Pass `&[T]`, ranges and IDs; no `.to_vec()`, `.clone()` or `String` building on a per-token or per-node path.
- **Load only what the document demands** (user, 2026-10-22). Every static table (macros, packages, fonts, hyphenation languages) is read through IDs and loaded or touched only when the document needs it. A document's cost scales with what it uses, never with what RushTeX supports. Structures: `2026-10-22-document-needs-measure.md`.
- **Speed target: at least 20× pdflatex on every document, aiming for 50×** (user, 2026-10-22), with zero shift. Only native translation reaches it: interpretation of LaTeX's macros is the cost (`get_token` about 50%). `bench_corpus.py` reports the ratio per document, and no commit lowers it.
- **No technical debt.** Each phase leaves one implementation per job, one table format, one pinned TeX Live, and a gate that catches drift (see "Debt guards").

### The five pillars (user, 2026-10-22: the engine must have all five; no item may trade one away)
1. **Native kernel on the exact core.** LaTeX's kernel, classes and supported packages are Rust code building node lists directly. No macro interpretation in the product. Items: P2, P2b, P3–P6, P7.
2. **Data as build-time tables.** `.tfm`, `.vf`, `.pfb` metadata, `.fd`, `.def`, `.cfg`, encodings, hyphenation and class parameters are generated by `rushtex-gen` into static tables. Each generator checks every emitted entry against its source file deterministically; data files are never matched against pdfLaTeX by trial. Items: D1, D2, P1, P5.
3. **Demand loading from a pre-scan.** One fused lexer pass gives the document's needs, as a bitset with its dependency closure, and only those tables and modules are touched. A first-lookup fault keeps it exact. Items: D3, D4, D4b.
4. **Per-block incremental compile, designed in from the start, not retrofitted at P8.** Every item from D1 on keeps state checkpointable at block boundaries: state reachable through IDs and arrays, no hidden global mutation, per-block ID arrays (D3). Its review asks: "can this be checkpointed, diffed and replayed per block?" P8 then only wires the cache and early cutoff.
5. **Zero-shift proof for every ported feature.** Each native command is proven against its macro version on the engine oracle, and the corpus stays at 85/85 zero shift in CI on the pinned TeX Live 2026 (A1, A1+). A feature without that proof is not shipped.

### Debt guards (each is a gate or a rule, not a hope)
- **One implementation per job.** The old approximate pipeline (`src/layout`, `src/math`, `src/tables`, `--native`) is frozen: no new work, retired at P7. Typesetting is the engine core only.
- **One product/oracle boundary,** enforced by the compiler: the `oracle` cargo feature holds `latex.ltx` interpretation, the format build and `engine_host`. CI builds without it.
- **One pinned TeX Live (a dated 2026 snapshot)** for the references, the generated tables and CI. Generated files carry a checksum, and CI regenerates and compares.
- **One table format library** (D1) for every generated table, versioned. No ad-hoc formats per module.
- **Every native command is proven twice** against its macro version (`RT_NATIVE` with identical boxes, state and written files), then corpus zero shift.
- **Kernel internals stay overridable** (port plan §5): a native routine checks one meaning word and yields to a redefinition.
- **Unported package in a release:** a clear error naming the package. The oracle fallback exists only in dev builds.
- **Budgets per commit:** time ratio, peak RSS, binary size, leak audit, zero shift.

### Phase 1. Foundations (the core and the boundary; everything later stands on them)
- [x] A0. `oracle` cargo feature: the product builds and passes its unit tests without `latex.ltx` interpretation, `engine_job`, `engine_host` or the format build.
- [x] A1. Pin a dated TeX Live 2026 snapshot (user, 2026-10-22: not 2023; our zero shift is already against pdfTeX 1.40.29 of TeX Live 2026, and users run the current kernel).
  - A manifest with package names, revisions and checksums, plus the LaTeX kernel date, committed and recorded in the binary.
  - CI installs that snapshot from the TeX Live archive, cached; Ubuntu's apt TeX Live is dropped.
  - The references, the generated tables and the oracle all come from it.
  - A yearly upgrade is one deliberate step: bump the pin, regenerate, and let the node-level diffs name every change.
  - The 2023 NewCMMath pin stays only for the frozen old pipeline's tests and leaves with it at P7.
- [x] A1+. CI gates what is local today: zero shift on the corpus, `scripts/leak_audit.py`, the ownership-check build and the engine probe suites, all against the pinned snapshot.
- [ ] A1b. Pinned-file suite, narrowed (user, 2026-10-22). Data files (`.tfm`, `.pfb`, `.vf`, `.fd`, `.def`, `.cfg`) are not probed against pdfLaTeX. They become build-time tables (`native-architecture.md`), and each generator checks every emitted entry against its source file deterministically: no trial and error. Code files only (`.sty`, `.cls`): one generated load probe each against pdfLaTeX (zero shift, or identical errors). Deferred to the port phase (P1 onward), where it proves each native package against its macro version.
- [ ] A2. Security for untrusted documents:
  - a file-read policy (the document's folder and the bundled tables; full kpathsea reach only in dev builds);
  - resource caps on nodes, tokens, file size, pages and expansions, each with a clear error;
  - fuzzing of the PNG, inflate and PDF-reading parsers (a dev-only tool, no runtime crates);
  - one CI corpus run with overflow checks on, to find silent wraparound where tex.web specifies a check;
  - `\pdfmatch` (`engine_regex`) moved from backtracking, which is exponential in the worst case, to a linear-time matcher that reproduces pdfTeX's match and submatch rules.
- [ ] A3. Balanced corpus: 15–20 real-world documents (articles, theses, papers with floats and bibliographies) picked from the arXiv package sample, added to the zero-shift gate.
- [ ] Z2. Build buffers reserved once: the per-line adjustment list, per-word hyphenation scratch, per-paragraph `par`/`breaks`/`carry`/active lists. Allocator share measured before and after.
- [ ] Z3. Token model M: macro texts and token lists in size-class blocks with one owner, or a count where TeX shares (§200 `token_ref_count`: `\let`, `\toks` copies, a body being read §390). Redefinition frees (§275 `eq_destroy`); `collect_tokens` deleted. This is the product's expander for user macros, so it stays.
- [ ] Z4. Capacity reserved from the source size; RSS flat per page on listings.
- [ ] H1. Hardware-counter tool `scripts/hw_profile.py`: `perf stat` on x86 Linux (CI and a floor-class machine), `xctrace` on macOS. Baseline for all 85 documents: instructions per glyph, IPC, L1 and last-level misses per page, branch mispredicts, plus bytes allocated and bytes copied per page (the §6d budgets). Budgets and floor in `native-architecture.md` §7a.
- [ ] B1–B2. Copies and clones removed from the expander and the core (`toks.get(..).to_vec()`, `nodes.get(..).to_vec()`, the math `Vec<Node>` returns).
- [ ] B3. Layout table beside every core record (size, fields, SoA or AoS and why).
- [ ] B4. Hot-loop census of the core and the expander over 85 documents (`profile_doc.py` plus H1): every function above 2% with its cost per call and its working set against the §7a floor, each one removed or justified. Known: mid-vector inserts (protrusion, math lists), per-call math vectors, name hashing per lexed name.
- [ ] B5. Algorithmic waste in the expander and core:
  - `macro_call` stores the parameter pattern's length in `Macro` at definition time, instead of scanning for `END_MATCH` on every call;
  - mid-vector `insert`/`remove`/`splice` removed (`cur.insert` in protrusion; `ml.remove` and `splice` in math), so they no longer shift everything after them;
  - measure whether ligature and kern program walks are hot; if so, a per-font 256-bit start gate and direct pair arrays.
- [ ] H2. Single-core throughput (`native-architecture.md` §7b), after B4 and only for loops B4 keeps:
  - SWAR in the lexer and the pre-scan;
  - line breaking: each node's widths computed once per paragraph into SoA arrays with prefix sums (`passes` recomputes them through a font lookup at every use, in every pass);
  - multi-accumulator packing;
  - SWAR match finding and checksums in DEFLATE;
  - a PGO release build;
  - an optional x86-64-v3 build;
  - a custom integer and fixed-point formatter in the PDF writer, not generic formatting (§6d).
  Each measured with H1 counters and per-kernel benchmarks.

### Phase 2. Tables and demand loading (shared by the oracle now and native later)
- [x] D1. Table library, std only, with tests and size reports: a static perfect hash with an 8-bit fingerprint per slot (name to ID and membership in one probe), SoA tables by ID, CSR lists (offsets plus IDs), bitsets, Roaring-style compressed bitmaps.
- [ ] D2. `rushtex-gen` skeleton plus the package registry. Fonts slice done (`2026-10-22-d2-font-tables.md`): 354 TFMs in one font-major, popularity-tiered, self-checked table; the engine reads no `.tfm` file. Still to do: `.fd`/NFSS and the package registry. Every generator self-checks: it re-reads each emitted table and compares every entry with its source file (pillar 2). For each `.sty`/`.cls`/`.clo`/`.fd`, recorded from an oracle run: its class (a–e of the port plan), options, `\RequirePackage` edges (CSR), the control sequences it defines, and its parameters. Generated, checksummed.
- [ ] D2b. Fonts by `native-architecture.md` §4a, in this order, each closed by zero shift 85/85 and the leak audit:
  - font programs split per glyph at build time, with subsets cached per (font, used-glyph set);
  - lig/kern pair tables compiled at build time, one probe per pair;
  - 16-byte per-character records per loaded (font, size);
  - expanded copies scaled once.
- [ ] D3. Document pre-scan, fused into the lexer's single pass (§6d: the source is lexed once, never twice): one pass over the source gives its command names, through the D1 hash, to a module `needs` bitset with its closure. Per-block ID arrays of what each block needs and reads (P8's dependency index from day one).
- [ ] D4. Demand loading in the core: hyphenation patterns only for the languages used, font metrics on first use, embedded font programs decompressed per used font.
- [ ] D4b. Hyphenation cache keyed by (language, `\lefthyphenmin`, `\righthyphenmin`, word), cleared when `\hyphenation` or patterns change; exact because §923 depends only on these. Hit rate measured on the corpus.
- [ ] D5. Measure: startup time and RSS per document against everything loaded; PDF size against pdflatex's, adding a deeper DEFLATE match search for release builds if ours is noticeably larger (the single-probe 32 KB table is fast but has no chains).

### Phase 3. Native translation (per `native-port-plan.md`, each command oracle-proven)
- [ ] P0 rest: `RT_PROFILE` time per macro, `RT_STATE`, `RT_NATIVE=cmd,…`, engine-against-engine `engine_boxdiff.py`, arXiv package-frequency sample.
- [ ] P1. Fonts and NFSS as generated tables (`.fd`, TFM, encodings, size functions); `\selectfont` and the size commands native. Metrics scaled once per used (font, size) and cached by ID (§568); embedded fonts subset once, at the end of the document.
- [ ] P2. Kernel core (counters, lengths, spacing, boxes, paragraphs, lists, sectioning, references, `\newcommand`, `\NewDocumentCommand`, keys, hooks, files): small2e, sample2e and lppl at zero format expansions.
- [ ] P2b. Single-run references (§6d): `\label`, `\ref`, `\pageref`, `\cite` and the contents lists resolved in memory, with no `.aux` reruns. Only pages whose resolved values changed are laid out again, until they stop changing. Output identical to pdflatex's final run.
- [ ] P3. Output routine and floats as an explicit state machine.
- [ ] P4. Tables, math, pictures.
- [ ] P5. Classes (article, report, book, their `.clo`; ltxdoc/doc; amsart, scrartcl, IEEEtran, exam): parameters as generated `const` tables, behaviour native.
- [ ] P6. Packages by real usage. Each `.sty` becomes data (tables generated by D2) plus behaviour (one Rust module with option bitflags and fixed hook slots). Class (a) libraries are not ported; native code subsumes them.

### Phase 4. Product
- [ ] P7. Zero dependency: no `latex.ltx`, tables and fonts in the binary, native is the default. Speed gate at least 20× pdflatex on every corpus document, zero shift 85/85, one typesetting run per document (P2b), and the §6d per-page budgets met.
- [ ] P8. Real-time incremental (the state is already checkpointable by pillar 4): block checkpoints, (content, state) cache, early cutoff, repagination until the breaks match, only changed pages shipped. Under 16 ms per typical edit.
